# 待办 22 · 前端可视化控制台

**优先级：主线之后。** 排在"代码工程重构"和"第②步技术路由"之后，主线基本稳定
再评估投入。这是工程化/体验层的锦上添花，不影响核心功能可用性。

## 要解决的问题

现在每一步都得敲命令行、记参数，结果散在各个 `outputs/` 目录里一个个找视频。
希望有个网页"控制台"：每个环节（质检/路由/感知/重定向/碰撞检测）给开关式入口，
不用记参数；能直接在页面上看结果；能看到"一段/一批视频现在跑到哪一步、结果如何"，
而不是只能盯终端里滚动的日志。

## 面向用户的主界面只放三样东西

1. 带骨架标注的原视频
2. 深度图
3. 最终的机器人 3D 动画

**"处理前 vs 处理后"这类对比视图不进主界面。** 它们是开发调试用途 —— 比如本次
迁移验证用的那份四宫格（`outputs/migration_check/fill_jar_migration_quad.mp4`，
第 2 格"不开碰撞纠正"、第 4 格"迁移前旧代码"），是给改代码的人看的，不是给用
数据的人看的。放主界面只会让用户以为那也是产物。这类东西归入单独的
**开发者/调试模式**。

## 架构目标：模块化，新方案即插即用

每个环节保持独立、职责单一。**未来新增一种技术方案（例如接入某篇论文的方法专门
处理第一人称视频），应当只在对应模块里新增一个实现，不需要改动其他模块的代码。**

这正是当前重构在走的方向，后面设计代码接口时要持续守住。已经落地的几条：

- 路由标签词表（`ViewClass` / `CameraMotion`）放在 `routing/schema.py`，
  `quality` 依赖 `routing` 而不是反过来 —— 路由不该依赖质检。
- 碰撞层不 import 上游任何东西，机器人构型以 `robot_cfg` 字典传入（只用
  `env_cls` / `scene_path` / `start_config` 三个键），换机器人不用改这一层的代码。
- 绝对路径只允许出现在 `configs/paths.yaml`，由 `tests/test_no_hardcoded_paths.py`
  钉住。

后面每加一个环节的实现，验收标准里都应该有一条：**"新增这个实现，改了几个别的
模块的文件？"答案必须是 0。**
