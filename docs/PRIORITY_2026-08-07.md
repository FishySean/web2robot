## 1. 视频质检 / 路由：暂停自主研发

已确认 **wangjufei** 那边在做类似工作，且**训练了专门模型做第一/第三人称识别**。
后续是**找他对接接口、复用他那边的成果**，不再自己重复做。

**不是作废已有工作。** 第①步已经可跑（`src/web2robot/quality/` + `src/web2robot/routing/`，
零安装、判决字段与基准 11×10 全一致、12 条信号无越阈、contact sheet 人眼确认过），
它就停在这个状态。上游环节先停，不删不改。

对接他那边时，我方这边**已经准备好的接合面**（这也是不重做的理由）：

- 路由标签词表在 `src/web2robot/routing/schema.py`（`ViewClass` / `CameraMotion`），
  是**路由拥有词表、质检依赖路由**，不是反过来。换成他的模型 = 在 `routing/` 里加一个
  实现、返回同一套标签枚举，**下游不用改**。
- 第①步的输出不是二元合格/不合格，每段通过的片段都带路由标签 —— 换成他的模型也要守住
  这条，否则第一人称那条分支会被饿死。
- 需要跟他确认的三件事：①他的模型输出是什么粒度（整段一个标签 / 逐帧 / 带置信度）；
  ②相机运动（动/静）他那边有没有，还是只有第一/第三人称；③调用形态（HTTP / 权重文件 /
  他的仓库）——决定我们是在 `routing/` 里包一层客户端还是直接加载权重。

## 3. 手上已有、可以直接支撑论文的东西

先记在这里，免得整理论文时想不起来散在哪：

- **HaWoR 深度突破**：在 HO-3D 标尺上把手部深度误差 11cm → 0.6cm、深度跟随由负转正。
  这是单目深度瓶颈的解法，也是"相机运动"这条路由分支存在的依据。
  证据在 `p3_gt_benchmark/`，路由对比在 `p4_hawor_routing/step16_hawor_vs_wilor.py`
  —— **这两处要从归档堆里捞出来，别跟着 archive 一起沉底**。
- **M7 hand_frame 约定**：末端帧必须 finger+y / thumb−x / palm+z，否则手掌转错。
- **M7 根模型手臂折叠修复**：`sample_config` 抄 R2 的 jitter/ou_step 与 M7 比例不符，
  按比例重算 + 重训后折叠和穿模都改善。
- **臂-躯 / 双手自碰撞后处理**（B0–B4）：胶囊 + 各向异性盒代理，保守门槛 `enter_thresh=0.04`，
  **手指关节从不改写**（指尖只触发手臂纠正）。实测左手 97/216 帧被纠正、右手 0 帧、
  手指数组逐位未动。
- **坏帧兜底** `traj_cleanup.py`：三级坏帧检测 + 长度感知填补，长空档标 `FILL_REST`
  并把状态往下传，不静默填成"看起来正常"的数据。
