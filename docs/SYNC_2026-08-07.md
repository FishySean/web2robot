## 2. 第①步质检：迁移完成，按约定的验收线跑过

你定的规矩是"每完成一个模块要重新跑一次验证"。这个模块的验证结果：

- 10 段片段重跑 67.4s
- **判决字段 11 项 × 10 段，全部一致**（verdict / reasons / needs_human_review /
  view_class / camera_motion / suggested_route / …）
- **12 条参与判决的信号，无一越过自己的阈值**
- 20 处数值漂移，最大 6.3% —— 这是 GPU 非确定性，不是回归
- contact sheet 人眼看过：手框、骨架、判决标签与基准一致；彩条对照正确判成
  `no_person / reject`

为什么不要求数值逐位相同：重跑一次 `cup_cpvH8gzUTko` 的 `torso_rate` 就从 0.4828
变 0.4655，n=58，差值正好 1/58 —— 一帧翻转。KeypointRCNN 在 GPU 上不是逐位确定的，
要求逐位相同的测试会在没人改代码时随机报红，很快就没人看。所以比对判的是
**判决字段逐字一致 + 每个信号没越过阈值**。工具在 `scripts/dev/diff_quality_run.py`。

新的跑法（薄壳已经处理好绝对路径解释器的问题）：

```bash
scripts/s1_quality_gate.sh data/videos/ --out outputs/qc.jsonl --viz outputs/ev/
envs/rt_env/bin/python -m unittest discover -s tests -v     # 10/10，秒级
```

### 顺手发现的一个脆弱点（是工具报出来的，不是我猜的）

`cand2_ZKCmHESpYgM` 的 `any_hand_rate` = 0.75，恰好等于 `min_hand_ratio` = 0.75，
**余量 0**。一帧翻转就会让 `low_hand_ratio` 这条 reason 出现/消失，把零容忍检查带红。
`low_hand_ratio` 本身只记录不否决，所以这是**选样本选压线了**，不是判据有问题。
真被绊到时该换样本，不是放宽容忍度。已记在 `tests/regression/README.md`。
