# evidence/ —— 论文/汇报要引的实验证据，**进 git，不许放 outputs/**

和 `outputs/` 的区别只有一条，但很关键：

| | `outputs/` | `evidence/` |
|---|---|---|
| 进 git 吗 | 不进 | **进** |
| 能重跑出来吗 | 能（跑一遍流水线） | **不一定** —— 依赖可能已经没了 |

`outputs/` 里的东西丢了就重跑。`evidence/` 里的东西丢了**可能就再也算不出来了** ——
外部数据集被清、第三方 checkout 被 `git clean`、3 GB 的 checkpoint 不在库里、
机器换了。这类结论一旦要写进论文，就不能再依赖那条脆的复现路径。

## 规矩

1. **小**。存的是最小可复核形态 —— 原始测量值（几十 KB 的 npz），不是 840 MB 的逐帧
   转储。大产物留在 `outputs/`，`evidence/` 只放"算表要用的那点数"。
2. **存测量值，不存结论数字**。存 3D 点，不存"11.0 cm"。换统计口径还能重算。
3. **秒级可复核，零重依赖**。评测代码走 `src/web2robot/eval/`，纯 numpy，不要 GPU、
   不要外部数据集、不要第三方仓库。
4. **每个数都有测试钉着**。论文里的数字和仓库里的证据脱钩是最坏的情况 —— 改了统计
   口径要当场变红，不是投稿前才发现。
5. **输给别人的那条也要在表里**。见 `depth_benchmark_ho3d/` 里 MC4 那条。
